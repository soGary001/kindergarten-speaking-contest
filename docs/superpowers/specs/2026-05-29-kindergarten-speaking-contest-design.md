# 国际幼儿园英语口语比赛网站 — 设计文档

- 日期：2026-05-29
- 状态：已与用户对齐，待审阅
- 项目路径：`~/Documents/GitHub/kindergarten-speaking-contest`（独立项目，与 pcrds-sys 无关）

## 1. 目标与背景

为某国际幼儿园的英语口语比赛做一个内部使用的网站。孩子对着麦克风说英语，屏幕实时显示识别出的内容并做简单的视觉反馈。比赛分小班、中班两个玩法。非公开使用，强调"尽量简单、易部署"。

成功标准：

- 现场一台电脑（Chrome / 国内网络）打开即可流畅运行两个玩法。
- 孩子说话停顿后，屏幕能在约 1-2 秒内把这一句的英文显示出来。
- 视觉风格活泼、抓眼球（Memphis 糖果明亮风）。
- 能打包成可双击运行的桌面程序（macOS `.dmg` / Windows `.exe`），拷到别的电脑就能用，且 API Key 不以明文形式暴露给使用者。

## 2. 玩法规则（需求）

### 小班 Junior

1. 系统从 `A C E F K S` 中**随机**给出一个大写字母，显示在屏幕中央。
2. 孩子连续说出以该字母开头的英文单词（单词量不限，每个孩子不同）。
3. 屏幕显示 **30 秒**倒计时。
4. 每识别出一个单词，以"气泡糖"形式弹出显示；首字母 = 当前字母的高亮绿色并带 ✓，否则灰白色（不打分、不淘汰，仅视觉反馈）。
5. 倒计时结束 → 自动回到开始页。

### 中班 Middle

1. 首页呈现 **6 个字母 `S D T F B G`**，字母做浮动/轻微旋转动画。
2. 孩子点选一个字母 → 该字母单独大字显示。
3. 孩子说出"以该字母开头的单词 + 一个包含该单词的短句"。单词和句子**同步**显示在屏幕上：单词用大号气泡糖（首字母对的高亮 ✓），句子用大圆体显示、其中的目标单词用黄色高亮框住。
4. 屏幕显示 **60 秒**倒计时。
5. 倒计时结束 → 自动回到开始页。

> 注：需求原文为"7 个左右"，实际给定字母为 6 个（S D T F B G），以给定字母为准。

### 智能体职责

只做**识别 + 首字母高亮**：把孩子说的话转成文字显示，并判断单词首字母是否等于当前字母。**不判断对错、不打分、不做语法评测。**

## 3. 技术方案

### 总体架构（单进程）

一个极简 **FastAPI** 应用，同时：

- 托管 `frontend/` 静态页面（原生 HTML/CSS/JS，**无构建步骤、不引前端框架**）。
- 提供 `POST /api/transcribe` 接口：接收前端上传的一段音频 → 调用小米 Mimo `mimo-v2-omni`（OpenAI 兼容接口）转写 → 返回识别文本。

API Key 保存在后端，前端永远拿不到。打包时 Key 编进可执行程序内部。

### 语音识别（"说完一句出一句"）

- 浏览器用 `getUserMedia` + `MediaRecorder` 持续录音。
- 用 Web Audio `AnalyserNode` 做静音检测（VAD）：检测到一段语音后出现约 **0.8 秒**静音，即认为"说完一句"，截出这段音频。
- 截出的音频片段（WebM/Opus，必要时转码）通过 `POST /api/transcribe` 上传，附带当前字母作为上下文提示，提高识别准确率。
- 后端调用 `mimo-v2-omni` 做转写，返回文本。
- 前端拿到文本：小班按空格/词拆成单词逐个气泡显示；中班把首个/目标单词与整句分别显示。
- `http://localhost` 属于浏览器"安全上下文"，麦克风可用，**无需 HTTPS 证书**。

> 技术风险与早期验证：`mimo-v2-omni` 通过 OpenAI 兼容 `chat/completions` 接收音频的确切格式（`input_audio` 的编码、采样率、容器格式）需要在实现第一步用一小段真实音频打通（冒烟测试）。若 omni 不支持该用法，则回退到 Mimo 提供的其它音频/ASR 能力或调整音频格式。

### Mimo 接入参数

- Base URL：`https://token-plan-cn.xiaomimimo.com/v1`
- 模型：`mimo-v2-omni`（音频转写）
- 兼容协议：OpenAI
- API Key：保存在后端配置（`backend/config.py`），打包时编入二进制；仓库中以占位/环境变量形式存放，真实 Key 不提交到版本库。

### 前端页面

- `index.html` — 开始页：两个大按钮（小班 Junior / 中班 Middle），Memphis 糖果明亮风背景。
- `junior.html` — 小班玩法页。
- `senior.html` — 中班玩法页（含首页字母动画 + 选字母后进入说话状态）。

### 错误与边界处理

- 麦克风权限被拒：页面给出友好提示，引导在浏览器允许麦克风。
- `/api/transcribe` 失败 / 超时：该句静默跳过（不阻塞倒计时），控制台记录；可选地在屏幕角落给一个轻量"没听清"提示。
- 识别为空 / 噪音：不显示气泡。
- 倒计时结束时若有请求在途：丢弃返回结果，直接回开始页。
- 网络中断：界面提示"网络异常"，倒计时照常走完。

## 4. 视觉设计

风格：**Memphis design，糖果明亮版**（方案 B）。

- 背景：浅蓝/奶油等 pastel 底色，散落圆形、三角、波浪、短条等几何形状（鲜艳点缀色：粉 `#ff8fab`、黄 `#ffd23f`、绿 `#06d6a0`、蓝 `#118ab2`、玫红 `#ef476f`、紫 `#c9b8f0`）。
- 大字母：居中超大号，带撞色投影。
- 识别单词：大号"气泡糖"圆角块，弹出动画（缩放+轻微旋转），对的绿色带 ✓、错的白灰色。
- 中班句子：大圆体，目标单词用黄色高亮框。
- 倒计时：右上角圆环。
- 中班首页 6 字母：彩色圆角气泡，上下浮动/轻微旋转，点击进入。

设计要求：活泼、抓眼球、对孩子友好；同时整体结构尽量简单。

## 5. 打包与分发

用 **PyInstaller** 把 FastAPI 应用 + 静态前端冻结为单个可执行程序。运行时：启动 `localhost` 服务 → 自动打开默认浏览器到本地地址。

- macOS：`build/build_mac.sh` → `.app` → 封装为 `.dmg`（在本机 Mac 构建）。
- Windows：`build/build_windows.bat` → `.exe`（**必须在 Windows 机器上运行**，PyInstaller 不支持跨系统打包）。

关于 API Key 的安全取舍（已与用户确认接受）：

- Key 编进二进制，不出现在网页源码、浏览器网络面板或明文配置文件中，对普通使用者不可见。
- 但这不是 100% 防逆向——拆包/逆向理论上可提取。任何"Key 随程序分发"的方案都无法做到绝对不可提取。
- 对该幼儿园内部比赛场景，此程度被接受。

## 7. 明确不做（YAGNI）

- 不做打分/评测/排名。
- 不做用户登录、数据库、成绩存储。
- 不做后台管理。
- 不做多语言切换（界面中英混排即可）。
- 暂不做 TTS 语音播报（后续可加）。
- 不做实时流式逐字转写（采用"说完一句出一句"的分段方案）。

## 8. 待实现时验证的假设

1. `mimo-v2-omni` 经 OpenAI 兼容接口接收音频的具体格式（实现第 1 步冒烟测试）。
2. 浏览器 `MediaRecorder` 输出的 WebM/Opus 是否可直接被 Mimo 接受，或需后端转码（如转 wav/mp3）。
3. 静音检测阈值与时长（约 0.8s）在现场环境噪声下的实际表现，需现场微调。
